## 7. MVP 최종 판정 (Decision Framework)

ClassFlow의 핵심은 **"단순히 코드가 에러 없이 돌아가는가"**가 아니라, **"교사가 복잡한 설명 없이도 5~10초 안에 도움이 필요한 학생을 식별하고 조치할 수 있는가"**입니다. 따라서 기능 작동 여부와 별개로 아래 기준에 따라 최종 판정을 내립니다.

### 판정 기준

- [ ] **PASS (통과 — 백엔드 및 실시간 연동 단계 진입 가능)**
  - 참여자 ≥ 3명
  - 도움 학생 발견 성공률 ≥ 70%
  - 평균 탐색 시간 ≤ 10초
  - 평균 만족도 ≥ 4.0점
  - 치명적인 UX 막힘 현상 없음
  - ➡️ *조치: 다음 단계(STEP 16: Supabase 데이터베이스 설계 및 실시간 인프라 구축)로 진행*

- [ ] **PARTIAL (부분 통과 — UI/UX 보완 후 재검증)**
  - 제품의 핵심 가치(Grid + Help Queue)는 인정받았으나, 특정 레이블이나 버튼 위치 문제로 탐색 시간 초과 또는 혼란 발생
  - ➡️ *조치: 백엔드 구현을 시작하지 말고, UI 레이아웃/문구 수정 후 추가 사용성 테스트 진행*

- [ ] **FAIL (실패 — 대시보드 구조 재설계 필요)**
  - 교사가 대시보드를 보고도 누구를 도와야 할지 전혀 감을 잡지 못함 (성공률 < 50% 또는 평균 만족도 < 3.0)
  - ➡️ *조치: Help Queue 및 Progress Grid의 정보 구조와 시각화 방식을 근본적으로 재검토*
