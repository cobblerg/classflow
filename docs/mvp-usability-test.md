# ClassFlow MVP 사용성 테스트 프로토콜 및 기록지

본 문서는 ClassFlow MVP의 핵심 가치("교사가 수업 중 도움이 필요한 학생을 빠르게 발견하고 조치할 수 있는가?")를 실제 교사 참여자를 통해 객관적으로 검증하기 위한 사용성 테스트 체크리스트 및 관찰 기록지입니다.

---

## 1. 테스트 목적

1. **발견**: 교사가 대시보드 화면을 보고 도움이 필요한 학생을 빠르게 찾을 수 있는가?
2. **우선순위**: 여러 명의 학생 중 누구를 먼저 도와야 하는지 우선순위를 쉽게 판단할 수 있는가?
3. **행동**: 학생 발견 후 상세 상태 확인, 도움 완료 처리, 피드백 전달까지 자연스럽게 행동으로 이어지는가?

---

## 2. 테스트 환경

- **기본 데이터**: STEP 13의 20명 × 10차시 데모 학급 (`AI와 피지컬 컴퓨팅 (데모)`)
  - 1~4차시: 공개(published) / 5~10차시: 비공개(unpublished)
  - 대표 학생 케이스 내장:
    - **학생03**: 3차시 진행 중, 🆘 도움 필요, 🙋 직접 도움 요청 대기 중 (최우선 대상)
    - **학생07**: 3차시 진행 중, 🆘 도움 필요, 직접 도움 요청 없음 (2순위 자가진단 대상)
    - **학생12**: 2차시 진행 중, 🤔 어려움 (3순위 관심 대상)
    - **학생15**: 2차시 완료, 🆘 도움 필요 (과제 완료 ≠ 이해 독립성 대상)
    - **학생01, 02, 04**: 정상 진행 및 완료 학생
- **기기 환경**: 노트북(권장 해상도 1366×768 이상) 또는 태블릿(iPad, Galaxy Tab 등)
- **진행 원칙**:
  - 참여자에게 앱의 조작법이나 기능 명칭을 미리 상세히 설명하지 않습니다.
  - 외부 스톱워치 또는 수동 시계로 시간을 측정하며, 참여자가 막히더라도 바로 알려주지 않고 10초 이상 관찰 후 최소한의 안내만 제공합니다.

## 4. Test 1 — 5초 인지 테스트 (First Impression)

> **진행 방식**: Teacher Dashboard 화면을 열고 참여자에게 정확히 5초간 화면을 보여준 뒤 화면을 가리거나 시선을 돌리게 합니다. 그 후 아래 질문을 구두로 질문합니다.

### 질문 1: "지금 도움이 필요한 학생은 누구인가요?"
- [ ] 도움 필요 학생 1명 이상 정확히 기억하여 답변함 (예: 학생03, 학생07, 학생09 중 1명 이상)
- [ ] 기억하지 못하거나 엉뚱한 학생을 답변함
- **답변한 내용**: __________________________________________________

### 질문 2: "그 중 가장 먼저 도와줘야 할 최우선 학생은 누구라고 생각하나요?"
- [ ] 학생03 (직접 요청 + 도움 필요)을 정확히 지목함
- [ ] 다른 학생을 지목함 (학생 번호: _______)
- [ ] 판단하지 못함

### 평가 체크:
- 도움이 필요한 학생을 1명 이상 정확하게 찾았는가? → [ ] 예  /  [ ] 아니오
- 가장 우선순위가 높은 학생을 정확하게 찾았는가? → [ ] 예  /  [ ] 아니오

- **처음 시선이 머문 위치**: [ ] 상단 Help Queue  /  [ ] 중앙 Progress Grid  /  [ ] 기타

## 6. Test 3 — 학생 상세 확인 (Context Understanding)

> **과제 지시**: "도움이 필요한 학생(학생03)이 어떤 차시에서 어떤 문제를 겪고 있는지 확인해 주세요."

- **탐색 경로**:
  - [ ] Help Queue의 [학생 보기 →] 버튼 클릭하여 이동
  - [ ] Progress Grid의 해당 빨간 셀(🔴)을 클릭하여 이동
  - [ ] 기타 경로 (우왕좌왕 후 이동 / 뒤로가기 반복 등)
- **확인한 정보** (참여자가 발견한 항목 체크):
  - [ ] 학생 번호 및 이름 (학생03)
  - [ ] 해당 차시 (3차시 버튼으로 LED 제어)
  - [ ] 진행 상태 (🟡 진행 중)
  - [ ] 이해 상태 (🆘 도움 필요)
  - [ ] 도움 요청 메시지 내용 ("버튼 입력값을 읽는 부분이 어려워요.")
- **별도 설명 없이 경로를 찾았는가?**: [ ] 예 (자연스럽게 진입)  /  [ ] 아니오 (힌트 필요했음)

---

## 7. Test 4 — 도움 완료 처리 (Action & Independence)

> **과제 지시**: "학생 자리로 가서 버튼 회로 문제를 해결해 주었다고 가정하고, 이 도움 요청을 시스템에서 처리 완료해 주세요."

- **실행 행동**:
  - [ ] 상세 화면 또는 Help Queue에서 [✓ 도움 완료] 버튼 클릭
- **도움 완료 후 상태 인지 확인**:
  - "도움 요청은 완료되었지만, 학생의 자가진단(이해 상태)은 여전히 '도움 필요'로 남아있을 수 있음을 이해하셨나요?"
  - [ ] 예 (요청 완료와 학생의 이해 상태가 독립적임을 인지함)
  - [ ] 아니오 (도움 완료를 누르면 학생 이해도도 자동으로 '이해함'으로 바뀔 것이라 예상함)
- **관찰 메모**: __________________________________________________

## 8. Test 5 — 교사 피드백 전달 (Feedback Loop)

> **과제 지시**: "학생이 스스로 복습할 수 있도록 '버튼 입력값이 0과 1 중 언제 바뀌는지 시리얼 모니터로 확인해 보세요.'라는 피드백을 남겨주세요."

- **입력 및 저장**:
  - [ ] 피드백 입력창에 텍스트 입력 후 [피드백 저장] 버튼 클릭 성공
- **학생 화면 확인**:
  - 참여자에게 학생03의 해당 차시 화면(`student/student-03/lesson/lesson-03`)을 보여줌
  - [ ] 학생 화면에 방금 작성한 교사의 피드백이 정확히 나타남을 확인함
- **수행 과정의 어려움**: [ ] 없음  /  [ ] 저장 버튼 인지 지연  /  [ ] 기타 (__________)

## 9. Test 6 — 학생 모드 체험 (Student Experience)

> **과제 지시**: "이번에는 학생 역할을 해보겠습니다. 학생 화면으로 이동하여 '학생03'을 선택하고, 3차시에 들어가서 진행 상태를 '완료'로 바꾸고, '이해했어요'를 눌러보세요."

- **탐색 경로**:
  - [ ] 상단 [👥 학생 화면] 링크를 통해 학생 목록(`student`)으로 이동
  - [ ] '03 학생03' 카드를 터치/클릭
  - [ ] 3차시 카드 클릭 후 상세 화면 진입
- **상태 변경**:
  - [ ] 진행 상태 '완료(🟢)' 선택
  - [ ] 이해 상태 '이해했어요(😊)' 선택
- **학생 UI의 직관성**:
  - [ ] 별도의 설명 없이도 어디를 눌러야 할지 즉각 파악함
  - [ ] 힌트나 안내가 필요했음 (사유: _________________________)

## 10. Test 7 — 차시 공개/비공개 제어 (Classroom Control)

> **과제 지시**: "교사 대시보드로 돌아와서, 다음 시간 수업인 '5차시(버튼과 부저)'를 학생들에게 공개 상태로 바꿔주세요."

- **실행 경로**:
  - [ ] Progress Grid 헤더의 '5차시' 아래 [🔒비공개] 버튼 클릭
  - [ ] 하단의 차시 관리 패널에서 '5차시' 스위치 클릭
- **확인**:
  - [ ] 🔓공개 상태로 변경됨을 즉시 인지함
  - [ ] 학생 화면에서도 5차시가 잠금 해제되어 접근 가능해짐을 확인함

- **데이터 보존 여부 확인**:

  - [ ] 5차시 공개 상태 유지
